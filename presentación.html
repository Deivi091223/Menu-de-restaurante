Ejemplo: la página Restaurante La Casona (repo Menu-de-restaurante): 4 categorías (Entradas, Platos fuertes, Postres, Bebidas), 11 platos, vista de cliente (arma su pedido) y de administrador (CRUD de platos). Analogía: el árbol genealógico.

1. ¿Qué es y cuándo lo aplico?

Traversing = moverse de un elemento a otro usando su parentesco (padre, hijos, hermanos), sin volver a buscarlo desde document.

Analogía en La Casona: un cliente toca el botón Agregar de la "Bandeja paisa". El mesero no recorre todo el restaurante preguntando "¿cuál plato era?": desde ese botón sube a su plato (article.plato), como quien sigue su árbol familiar hasta la casa correcta, y desde el plato lee el nombre (su hijo h4) y el precio (su hijo span). Si ya tengo un elemento, llego a sus parientes desde él.

SituaciónElemento repetidoQué pasaHerramientas
Menú de restaurantePlato con nombre y precioEl botón Agregar suma el plato a una lista de pedidoclosest, querySelector

Hay muchos platos y un botón dentro de cada uno. Desde el botón que recibió el clic necesito llegar a su plato, no a otro. Sin traversing tendrías que ponerle un id a cada plato y a cada botón.

boton.closest(".plato");   // una línea sirve para todos los platos

2. ¿Cómo funciona? El DOM es un árbol genealógico

Estructura real de cada plato en el repo (tomamos como "yo" el botón Editar):

Más arriba: div.lista-platos → section.categoria → section#menu → main → div#app. Dentro de #app cada categoría (Entradas, Platos fuertes, Postres, Bebidas) agrupa sus platos.

Si el pariente no existe, el resultado es null (como pedir el hermano de un hijo único).

const nombre      = plato.firstElementChild;        // h4  (hijo mayor)
const descripcion = nombre.nextElementSibling;      // p   (su hermano)
const precio      = descripcion.nextElementSibling; // span (hermano del hermano)

¿Por qué "Element"? El DOM también cuenta texto y espacios del HTML como nodos ("fantasmas" del árbol). firstChild, childNodes, parentNode y nextSibling pueden devolver un salto de línea; las versiones Element solo cuentan las etiquetas ("personas").

Delegación de eventos y CRUD

Los archivos usuario.js y admin.js usan delegación de eventos en el contenedor #app. Cada archivo atiende solo sus acciones. Desde e.target se sube hasta el botón y hasta su plato.

Analogía: dos meseros especializados comparten la entrada: uno atiende al cliente y el otro al administrador; cada uno identifica la acción y va a la mesa correcta.

// En admin.js y usuario.js se escucha desde el contenedor común.
app.addEventListener("click", (evento) => {
  // Encuentra el botón aunque el clic ocurra en un elemento dentro de él.
  const boton = evento.target.closest("button[data-accion]");
  if (!boton) return; // Ignora los clics que no sean de una acción.

  // Encuentra la tarjeta del plato; puede ser null en botones generales.
  const plato = boton.closest(".plato");

  // admin.js ejecuta CRUD; usuario.js gestiona carrito e historial.
  // Cada archivo ignora las acciones que pertenecen al otro.
});
